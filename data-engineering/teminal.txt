 2단계. 안심구역 데이터를 data/raw 폴더에 복사
------------------------------------------------------------------------------
   파일 (예시 이름)                      내용
   교통카드이용내역....csv               교통카드 이용내역(수도권). 2024년 8월. 여러 파일이면 전부
   노선정보.csv                          노선 정보
   노선정류장정보.csv                    노선정류장 정보
   정류장정보.csv                        정류장 정보
   seoul_flow_time_202408.csv            SKT 시간대별 유동인구
   seoul_flow_wkdy_202408.csv            SKT 요일별 유동인구

!! 파일 이름은 바꾸지 말고 실제 이름을 메모해 둔다. 4단계에서 CONFIG에 적는다.
!! 데이터가 DB(SQL)로만 제공되면 csv로 저장해서 둔다. 교통카드는 전체가 매우 크므로
   가능하면 9401과 9401 정류장 기록만 꺼낸다 (아래 예시. 테이블 이름은 실제 이름으로)
     1) 노선정보에서 노선번호 9401의 노선ID 확인
          SELECT DISTINCT ROUTE_ID, ROUTE_NMA FROM 노선정보 WHERE ROUTE_NO = '9401'
     2) 그 노선ID의 정류장ID 목록
          SELECT DISTINCT STTN_ID FROM 노선정류장정보 WHERE ROUTE_ID = '위에서 찾은 ID'
     3) 교통카드: 9401 기록 + 9401 정류장에서 탄 모든 노선 기록 (분담률 계산에 필요)
          SELECT * FROM 교통카드이용내역
          WHERE OPRAT_DATE LIKE '202408%'
            AND (TCBO_ROUTE_ID = '위에서 찾은 ID' OR TCBO_GIN_STTN_ID IN (2번 목록))
   VIRTL_CARDNO(가상카드번호)는 코드가 읽지 않는다. 꺼낼 때 빼도 된다.

 4단계. 설정(CONFIG) 확인하고 고치기
------------------------------------------------------------------------------
--- 4-1. (선택) 리허설: 가짜 데이터로 먼저 돌려보기 ---
[셀 4]
      %run RunAll.py --dummy
   마지막 줄이 "반출 패키지 -> ...\exportDummy (44개 파일)" 이면 코드는 정상
   (exportDummy 는 가짜 결과라 반출하지 않는다)

--- 4-2. 컬럼 이름 확인 ---
[셀 5]  각 파일의 첫 줄(컬럼 이름)만 본다
      import pandas as pd
      for f in ["노선정보.csv", "노선정류장정보.csv", "정류장정보.csv", "교통카드이용내역....csv"]:
          print(f, list(pd.read_csv("data/raw/" + f, nrows=0, encoding="cp949").columns))
   (UnicodeDecodeError 가 나면 encoding="utf-8" 로 바꿔서 다시)
   컬럼 이름에 정의서의 영어 이름(ROUTE_ID, STTN_SEQ, TCBO_CAR_ID ...)이 들어 있으면 OK
   "운행일자(OPRAT_DATE)" 처럼 한글이 붙어 있어도 OK. 영어 이름이 아예 없으면 메모해서 나온 뒤 수정

--- 4-3. RunAll.py 열어서 고치기 ---
1. 주피터 파일 목록에서 RunAll.py
2. "CONFIG = {" 아래 항목을 2단계에서 메모한 실제 파일 이름으로 (따옴표 " " 와 쉼표 , 는 지우지 말 것)

   "card_file": "교통카드이용내역*.csv",     <- 교통카드. 여러 파일이면 공통 부분 + * (예: "card2024*.csv")
   "route_file": "노선정보.csv",
   "route_stop_file": "노선정류장정보.csv",
   "stop_file": "정류장정보.csv",
   "card_ym": "202408",                      <- 교통카드에서 쓸 달 (SKT와 같은 달. 파일에 다른 달이 섞여 있어도 이 달만 씀)
   "holidays": ["20240815"],                 <- 교통카드 기간의 평일 공휴일
   "turnaround_name": "서울역버스환승센터",   <- 회차 정류장 이름 (01단계 출력의 "회차 seqNN"이 서울역인지 확인)
   "flow_file": "seoul_flow_time_202408.csv",
   "wkdy_file": "seoul_flow_wkdy_202408.csv",
   "std_ym": "202408",                       <- SKT 기준년월 (교통카드와 같은 달)

3. Ctrl + S 로 저장

--- 4-4. SKT 기준년월 확인 ---
[셀 6]
      pd.read_csv("data/raw/seoul_flow_time_202408.csv", sep="|", usecols=["STD_YM"], dtype=str)["STD_YM"].unique()
   '202408' 이 있으면 그대로. 없으면 결과 중 교통카드와 같은 달로 "std_ym" 을 바꾸고 저장


------------------------------------------------------------------------------
 5단계. 실행 (두 번: 이탈 없음 / 120분 이탈)
------------------------------------------------------------------------------
줄 서기 계산에서 "오래 못 타면 줄에서 빠지는 사람(이탈)"을 넣은 버전과 뺀 버전을 둘 다 만든다.
두 번 돌려도 결과 폴더와 로그가 따로 생겨서 덮어쓰지 않는다.

   버전          명령                              결과 폴더            로그
   이탈 없음     %run RunAll.py                    export/              data/processed/run_log.txt
   120분 이탈    %run RunAll.py --patience 120     exportQuit120/       data/processed/run_logQuit120.txt

[셀 7] 첫 번째: 이탈 없음
      %run RunAll.py

   끝나면 마지막 줄 확인:  반출 패키지 -> ...\dsz-bus-2026\export (70개 안팎)

[셀 8] 두 번째: 120분 이탈 (셀 7이 끝나서 왼쪽이 숫자로 바뀐 다음에 실행)
      %run RunAll.py --patience 120

   끝나면 마지막 줄 확인:  반출 패키지 -> ...\dsz-bus-2026\exportQuit120 (70개 안팎)

   두 번째부터는 02단계(교통카드 훑기)를 다시 하지 않아서 훨씬 빨리 끝난다 (아래 "02 저장본")
   !! 시간이 부족하면 첫 번째(이탈 없음)를 먼저 끝내고 반출 신청부터 해 둘 것

[02 저장본] 교통카드 전체를 훑는 02단계는 1시간 넘게 걸려서, 처음 한 번 결과를 저장해 둔다
   저장 위치: data/processed/cardCache/ (card, stopBoard 등 parquet + meta.json)
   다음 실행부터 02단계에 아래 줄이 나오면 저장본을 읽은 것 (몇 초)
      02 저장본 사용 (cardCache/, 교통카드를 다시 훑지 않음. 다시 훑으려면 --recard)
   코드(03~10번, CONFIG의 tau·반경 등)를 고쳐서 다시 돌려도 저장본을 그대로 쓴다
   아래가 바뀌면 자동으로 다시 훑는다: 교통카드 파일(목록·크기·수정시각), card_ym, 9401 노선ID, 정류장 정보, stop_merge_m
   일부러 다시 훑고 싶으면:   %run RunAll.py --recard
   !! 02단계가 끝나기 전에 멈추면 저장본이 만들어지지 않는다 (다음 실행에서 처음부터)

- 셀 왼쪽이 [*] 로 바뀌면 실행 중. 숫자로 바뀌면 끝. 실행 중에는 다른 셀을 실행하지 말 것
- 진행 단계가 순서대로 출력된다
      01. 9401 노선ID와 정류장 순서
      02. 교통카드 ...                <- 처음 한 번만 교통카드 전체를 훑어서 제일 오래 걸림 (다음부터는 저장본)
      03. 버스 한 대씩 ...
      04. 정류장x시간대 ...
      05 + 06. SKT 유동인구 ...       <- 두 번째로 오래 걸림
      07. / 08. / 09. / 10.

두 번 다 같은 단계가 출력된다. 07단계 "[평일] {...}" 줄에서 patience_min 이
   첫 번째는 '이탈 없음', 두 번째는 120.0 이면 맞게 돈 것


------------------------------------------------------------------------------
 6단계. 실행 결과 점검 (숫자만 메모. 원본 행은 적지 않는다)
------------------------------------------------------------------------------
01단계
   "노선 정보에서 9401 노선ID 후보 N개" 표 -> 노선명칭이 9401(구미동~서울역) 같은지
   "서울 구간 seq A~B (N개)" -> 서울 도심 정류장이 11개 안팎인지
   "회차 seqNN ..." -> 서울역버스환승센터인지 (아니면 CONFIG turnaround_name을 실제 정류장 이름으로)
02단계
   "다른 정산사업자 정류장ID 통합 (이름 같고 30m 안): N개" -> 경기 노선이 서울 정류장을 다른 ID로 쓰는 경우를 합친 수
      (0개면 그대로 진행. 너무 많으면(수십 개) 이름이 흔한 정류장이 섞인 것이니 메모)
   "노선ID별 기록 수" -> 9401 노선ID 하나에 기록이 몰려 있는지
   하차기록없음_비율 (보통 몇 % 이내), 하루_운행차량
03단계
   승차정류장_연결비율 -> 90% 이상이어야 정상
   정류장순서_일치도   -> 0.9 이상이어야 정상 (낮으면 정류장 순서·운행 나누기가 틀린 것)
   하루_운행횟수
   30초이내_연속도착_비율 -> 몇 % 이내가 정상. 높으면(10% 이상) 같은 버스가 두 번 잡힌 것일 수 있음
   재차_41명초과_운행비율, 운행별_최대재차_95백분위 -> 41을 자주 넘으면 입석이나 좌석이 더 많은 버스(2층 등)가 섞인 것
   "노선ID ...는 정류장이 같아서 같은 9401로 합침" -> 9401이 노선ID 여러 개로 나뉘어 있었다는 뜻 (정상 처리)
   "가상 정류장 N개 분석 제외" -> 서초IC(가상) 같은 고속도로 위 가상 정류장이 빠졌는지
04단계
   "서울 구간 평일 18시" 표: n_buses(시간당 대수), headway_obs(평균 배차), gap_cv(몰림), full_bus_share(만석 비율)
   "정류장별 9401 분담률" -> 0~1 사이인지
07단계 (두 버전 비교, 숫자만 메모)
   "[평일]" 아래 표에서 순천향대학병원(seq38) 18시의 wait_total_min(기대 대기 분), give_up_share(못 타고 남은 비율)
   -> 이탈 없음 / 120분 이탈 두 값을 나란히 메모. 체감(18시 약 1시간)과 가까운 쪽을 확인
08단계
   "검증: {...}" 줄 -> 적중률(위험예측중_실제만석), 포착률, 재현오차_WAPE 숫자 메모
      (시간 분할 검증 생략 메시지가 나오면 22일 이후 평일이 3일 미만인 것. 그대로 진행)
09단계
   "장표 대표 정류장·시간: {...}" -> stops에 업무/상업·관광/환승/말단 4곳이 다 잡혔는지
      (빠진 곳이 있으면 CONFIG "deck_stops"의 이름을 실제 정류장 이름 일부로 바꿔서 다시)
   "⚠ 장표 그림 ... 생략" 이 나오면 그 메시지만 메모 (나머지 그림·표는 정상 반출됨)

결과 파일: 작업 폴더/export/ 와 exportQuit120/ 각각 안에
      ExportManifest.md       <- 반출 신청서에 첨부할 파일 목록
      tables/  (CSV 33개 안팎. 20~27번은 장표용, 27DeckNumbers = 장표 빈칸(○)에 들어갈 숫자 모음)
      figures/ (그림 37개: E1~E5 탐색, F0~F16 결과·검증·서비스, S13~S19 장표용(숫자 = 장표 쪽))

------------------------------------------------------------------------------
 문제가 생겼을 때
------------------------------------------------------------------------------
에러는 출력 맨 아래 줄을 보면 된다. 자주 나올 만한 것:

FileNotFoundError / 교통카드 파일이 없습니다
   -> 파일 이름이나 위치가 다름. 2단계 파일 위치와 4-3 CONFIG 파일 이름 확인

KeyError: ... 에 ROUTE_ID 컬럼이 없습니다. 실제 컬럼: [...]
   -> 파일 컬럼 이름이 정의서와 다름. 에러에 나온 실제 컬럼 목록을 메모해서 나온 뒤 수정

노선 정보에 노선번호 9401가 없습니다
   -> 노선번호 표기가 다름 (예: "9401번", 앞에 공백). 노선정보에서 9401이 들어간 행을 찾아
      ROUTE_ID 를 메모하고 CONFIG "route_id": "그 ID" 로 넣은 뒤 다시 실행

교통카드에 노선ID [...] 기록이 없습니다
   -> 노선정보의 ROUTE_ID 와 교통카드의 TCBO_ROUTE_ID 번호 체계가 다른 것.
      교통카드에서 9401 정류장에 자주 나오는 TCBO_ROUTE_ID 를 확인해서 CONFIG "route_id" 에 넣기

승차정류장_연결비율이 낮음 (예: 10%)
   -> 노선정류장 정보의 STTN_ID 와 교통카드 정류장ID 체계가 다른 것. 메모해서 나온 뒤 수정

학습 가능한(자리가 넉넉 & 유동인구 있는) 칸이 0개
   -> CONFIG의 "tau": 0.6 을 0.8 로 올려서 다시 실행

[반출 차단] ... 원자료 컬럼 포함
   -> 반출 규칙 검사에 걸린 것. 코드 수정이 필요하니 메시지를 메모해서 나온 뒤 수정

MemoryError / 커널이 죽음(Kernel died)
   -> 메모리 부족. 교통카드를 2단계 SQL처럼 9401 관련만 꺼내서 다시. 다른 프로그램을 닫고 Kernel -> Restart

!! 에러 메시지를 메모할 때 원본 데이터 값(인원, 카드번호, 좌표 등)은 적어 나오지 않는다.
   에러 종류와 파일/컬럼 이름만 적는다.
